# REPORT_HUD_Layout_Refresh_v0.33

## 日期
2026-03-08

## 本轮目标
- 将桌面 HUD 从四角散点式改为左右连续纵向堆叠
- 压缩武器/被动占高，释放主战斗区视线
- 移除顶部横幅，把楼层与区域信息收进地图面板
- 强化楼层主题化背景、粗糙手绘边框与中文字号层级

## 完成内容
- 左侧 HUD 改为 `角色状态 -> 战斗属性 -> 武器栏 -> 被动栏` 的紧凑纵向结构
- 右侧 HUD 改为 `地图 -> 道具栏 -> 战斗记录` 的紧凑纵向结构
- 武器栏重做为固定 6 格横排，按武器上限显示，空槽保留占位避免布局抖动
- 被动栏同步改为 6 格横排，并补摘要文案，减少旧版长清单感
- 顶部横幅停止在战斗内显示，楼层名、区域名、房间类型改为地图面板内部标题
- 新增右下 `战斗记录` 面板，显示击杀、评分、存活时间、连战
- 左右侧新增整列主题背景板，继续跟随楼层切换纹理与雾色
- HUD 面板边框改为更粗、更不规则的手绘记录板风格，弱化标准圆角 UI 感
- 提升面板标题、中文标签、地图标题、心形血量等字号，修正“只放大数字”的不平衡问题
- 为整个 `mainLayout` 新增程序化随机墨迹外框，统一收口桌面战斗舞台
- 为左右空白区新增程序化墨迹装饰层，避免 HUD 外侧留白像未设计区域
- 为中间战斗区新增独立随机内框和轻度脏污层，形成“整页外框 + 战斗内框”的双层结构
- 墨迹边框改为运行时 SVG 随机生成，并在进入战斗、继续游戏、窗口缩放、楼层主题切换时刷新
- 将 `sidebar-section`、`stat-row`、`hero-hearts`、`map-room-badge`、`run-stat-cell`、`equipment-slot`、`item-cell` 等框体统一切换到同系随机墨迹边框
- 将中间战斗区的墨迹内框与脏污层大幅弱化，避免与房间墙体天然边界叠出双重框线
- 将大面板、小条目、槽位、地图容器的底板轮廓从圆角矩形改为不规则裁切轮廓，消除“边框像墨迹、底形仍是圆角卡片”的违和感
- 将左右 HUD 容器从窄列定位改为完整侧区容器，先铺满左右背景，再让真实 HUD 在各自区域内部居中
- 增加 HUD 列宽并缩小中央战斗区比例，减少两侧留白
- 在中央战斗区左右补充分隔装饰带，强化三栏之间的视觉分区
- 根据实机反馈移除整页大墨迹外框，避免墨迹压入游戏内部影响画面
- 将左右侧区背景从高存在感纹理改为更克制的暗石板/纸面混合底，并将三栏分隔装饰改为简化压边
- 修正三栏几何比例：将中心战斗区恢复为严格 `56.25%` 宽度的正方形，并让左右 HUD 主板重新占满侧区高度，恢复上下对齐
- 修正第六层 HUD 可读性问题：移除高对比核心层纹理对 HUD 底板的直接干扰，改为更深、更稳的低频暗红黑材质
- 按 `DESIGN_Cinematic_HUD_Art_Direction_v0.33` 启动 `Sprint A`，重做左右侧区基底为低噪声暗翼，并把记录板与侧翼材质彻底分层
- 侧区基底改为“深色主底 + 极弱竖向结构 + 顶部轻雾 + 靠近战斗区一侧边缘压光”的四层结构，避免继续使用高频重复纹理
- 三栏交界处的分隔带改为更宽但更轻的软边过渡，让中心战斗区与侧翼之间像镜头压边，而不是硬切线
- HUD 主板底材同步改为更纯净的旧纸/手稿板面，降低与侧区基底的材质重复感
- 按 `Sprint B` 建立 HUD A/B/C/D 四级面板规则：角色状态与地图升级为 A 级主板，属性/道具/战斗记录收为 B 级，武器/被动降为 C 级，条目/小格/槽位统一退为 D 级
- 统一压低小框墨迹和槽位边框浓度，避免每一块统计条、统计格、装备槽都成为视觉焦点
- 角色状态与地图面板提高标题权重、边框完整度和板面稳定度，让主信息面板真正压住次级信息
- 武器栏、被动栏、道具格、统计小格全部改为更轻的材质与高光，只保留同语系轮廓，不再与大面板抢气质
- 启动 `Sprint C`，为暂停、商店、宝箱、武器箱、升级界面建立共用的演出层底板、卡片和按钮语言，统一 Overlay 的电影感
- 暂停菜单从“半透明矩形按钮列表”改为手稿面板式中层界面，并同步修正悬停与点击热区，避免视觉尺寸和交互判定错位
- 商店、宝箱、武器箱、升级界面全部切换到同一套暗黑手稿演出面板，去掉旧的纯色方框和临时调色板风格
- 重做开局武器选择页，使其回到第一层菌丝/手稿风格，去掉蓝色网页面板感，改为和正式 HUD 同世界观的起始记录板
- 启动 `Sprint D` 的楼层主题精修，将第五层 `courtyard` HUD 主题从灰绿系改为深红手稿系，增强压抑感与电影气压
- 将 Overlay 演出层的底板、标题、卡片、按钮颜色抽到楼层主题变量，令暂停、商店、宝箱、武器箱、升级界面也随楼层同步换气质
- 继续清理第五层残留旧色表：将墨迹舞台 palette 的 `courtyard` 映射改为深红系，并把商店/升级/武器箱中的新武器、等级、警告、价格、锁定等状态色抽到主题变量，避免第五层仍出现灰绿或荧光串色
- 继续清理外部 UI 的旧网页感：将 `ui-screen / ui-panel / ui-btn / settings / loading / story / menu` 的主色与底材收回 HUD 主题变量，使开场页、设置页、加载页与主 HUD 共享同一套暗黑手稿电影语言
- 将结算画面从独立蓝黑面板改为 Overlay 手稿面板体系，并把胜利/失败/中性标题色与统计高亮一并切到楼层主题状态变量
- 继续清理内联主题串色：将剧情页强调文本、序章遮罩文字、设置页主题下拉框与 Overlay 按钮文字高亮统一回楼层主题变量，减少局部冷蓝/通用白残留

## 风险控制
- 保留原有 `updateMiniMap()`、道具格子、分数系统与移动端 HUD 链路，不改核心玩法逻辑
- 顶部横幅未直接删除 DOM，仅停止显示，降低与既有显隐控制冲突的风险
- 武器/被动改为固定槽位后仍复用现有 `this.weapons` 与 `passives.getOwnedPassives()` 数据源，避免重新定义背包协议
- 舞台墨迹框使用运行时 CSS 变量注入，不覆盖既有 HUD DOM 结构，降低与并行开发冲突的面积
- HUD 子框体改为共享随机边框变量，而不是逐个硬编码图片，方便后续继续细调墨迹密度与统一风格

## 待验证项
- 桌面端 `4x5` 道具栏在低分辨率下是否仍有足够呼吸感
- 左右整列背景板在最亮楼层主题下是否会压缩战斗画面对比
- 6 格武器/被动槽在高等级局内是否足够清晰区分激活、超武、空槽状态
- 墨迹外框在极窄或极宽屏幕比例下是否会出现局部过密、滴落过长或遮挡 HUD 文字
- HUD 小框体在同一轮随机生成下是否已经足够统一，还是需要把“大面板 / 小条目 / 槽位”三套墨迹风格再进一步拉开
- 新的侧区基底在不同楼层主题下是否已经足够“安静”，还是仍需要继续压低竖向结构与边缘高光
- 侧区与 HUD 主板之间的层级分离是否已经成立，还是需要在 `Sprint B` 继续减少主板内部纹理噪声
- A 级面板与 B 级面板的权重差是否已经足够明显，还是需要在 `Sprint C` 继续提升暂停态和主地图的戏剧性
- C/D 级小框是否已经足够安静，还是仍有局部槽位和统计格显得过重
- Overlay 面板统一后，暂停/升级/商店是否已经足够像同一套电影语言，还是还存在局部旧色块和旧描边残留
- 开局武器选择页是否已经和第一层主 HUD 同世界观，还是还需要继续减少“首页专题页”感
- 第五层深红 HUD 是否已经足够稳重高级，还是需要继续细调红金比例与地图高亮对比
- 楼层主题进入 Overlay 后，各层演出界面是否已经形成足够明确的情绪差异，还是仍有局部界面残留统一默认色
