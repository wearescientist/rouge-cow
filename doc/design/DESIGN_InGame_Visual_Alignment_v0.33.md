# DESIGN_InGame_Visual_Alignment_v0.33

## 目标

让游戏内视觉、渲染和 UI 追上当前封面、主菜单和无缝开场的气质，减少“包装像独立游戏，进入游戏像功能原型”的落差。

本方案不讨论新玩法，不讨论新剧情，只讨论：

- 游戏内 HUD
- 游戏内菜单与面板
- 房间氛围与后处理
- 战斗反馈视觉语言

---

## 当前判断

当前项目已经不是“没有美术方向”，而是“方向不一致”。

外层包装已经建立了比较明确的气质：

- 安静
- 阴冷
- 叙事感强
- 有一点童话感和不安感

但游戏内层仍然主要表现为：

- HUD 和面板偏工具化
- 暂停界面偏临时绘制
- 分数、状态、数值反馈偏街机化
- 光照和后处理存在，但没有稳定服务于统一气氛
- 进入战斗后，视觉风格从“故事感”切回“原型感”

所以问题不在“某个元素不好看”，而在于：

**封面、开场、游戏内，缺少同一套视觉语法。**

---

## 主要落差点

### 1. HUD 气质不对

目前 HUD 有明显“功能优先”痕迹：

- 顶部中央分数条 `#topScoreBar` 偏街机记分牌
- `#scoreValue` 的黄字发光非常抢戏
- 血量、分数、击杀、房间统计没有明确主次
- 道具格子和侧栏更像调试辅助区，不像沉浸式 HUD

结果：

- 游戏核心注意力被“数字系统”抢走
- 画面重心偏 UI，不偏角色和房间
- 和开场的电影感完全不是一个系统

### 2. 暂停菜单和设置面板过于原型化

当前暂停界面是 Canvas 里直接画遮罩、矩形按钮和文本：

- `drawPauseScreen()` 仍是典型开发期菜单
- 文案前有 emoji，破坏整体气质
- 按钮形态和主菜单、开场字幕、设置弹窗不是同一语言

设置弹窗虽然已经模块化，但视觉上仍是“标准弹窗 + 表单控件”，缺乏世界观感。

### 3. 武器选择页和故事包装不统一

武器选择页面仍然更像系统页：

- 壳层还在，但缺乏“下洞前抉择”的仪式感
- 与开场动画的情绪连接不够紧
- 从黑场字幕到武器卡片，视觉语言有断裂

### 4. 房间氛围系统有了，但没有成为主导语言

项目当前已经有：

- `SimpleLighting.js`
- `TiltShiftSystem.js`
- 一些 HD-2D / 武器视觉 / 暗角相关模块

这说明问题不是“技术缺失”，而是“使用方式分散”：

- `SimpleLighting` 仍偏功能性叠加
- 环境光偏亮，主要目标是“别压暗”
- 暗角和景深更像附加滤镜，而不是房间气氛设计的一部分
- 缺少按状态切换的氛围层，例如：
  - 战斗中
  - 房间清空后
  - 精英房
  - Boss 前夕
  - 低血量时

### 5. 战斗反馈很多，但风格没有统一

现在系统里已经有：

- 伤害数字
- 血迹
- 命中特效
- 屏幕震动
- 粒子

但这些反馈更偏“有效”，不够“有审美方向”。

当前问题主要是：

- 颜色体系没有完全统一
- 强反馈偏亮、偏散
- 没有明确区分“痛感反馈”和“奖励反馈”
- 视觉节奏多，但不够克制

## 视觉方向建议

## 核心关键词

- 潮湿
- 黑土
- 月光
- 枯草
- 洞口
- 童年记忆被污染
- 克制而不空

## 游戏内应采用的统一语言

### 1. 色彩

主色建议压到以下区间：

- 深蓝黑：背景和暗部
- 灰绿：地表、洞口、雾层
- 暗金：交互重点、可选项、武器抉择
- 暗红：受伤、危险、污染
- 冷白：字幕、关键提示、重要标题

避免继续大量使用：

- 纯黄高亮分数字
- 纯蓝 hover 框
- 纯白硬描边按钮

### 2. UI 材质

统一成“旧纸板 + 洞口木牌 + 受潮金属”的感觉，而不是普通游戏面板。

表现原则：

- 面板边缘不需要太规整
- 阴影偏软，不要网页感投影
- 按钮优先像铭牌、木牌、写字条
- 交互态用亮度和轻位移，不用蓝色系统 hover

### 3. 文本

文本系统建议分三层：

- 标题层：手写 / 童话感强
- UI 层：仍可用当前中文字体，但要减少过大字号和过厚阴影
- 数值层：更收敛，减少街机感

### 4. 动效

不要多，而要稳。

推荐保留：

- 慢速漂移
- 微弱呼吸
- 黑场过渡
- 受击瞬间短促闪白/压暗
- 房间清空后的环境松弛

不推荐继续堆：

- 高频弹跳
- 大量高亮发光
- 太多独立 UI 小动画

## Phase 划分

## Phase 1：先把“最掉价”的部分抬起来

这是最值得立刻做的一阶段。

### 目标

不重写核心系统，只通过 HUD + 暂停 + 面板统一，让玩家一进游戏就不出戏。

### 范围

1. 重做主 HUD

- 取消顶部街机式分数条主视觉地位
- 分数降级到次级信息
- 血量、当前武器、层数、金币这类信息重组主次
- 道具格子改成更沉浸的侧栏或角落布局

2. 重做暂停界面

- 不再使用 Canvas 里矩形框临时绘制的按钮风格
- 改成与主菜单一致但更克制的游戏内面板
- 去掉 emoji
- 暂停页应像“夜里翻开的旧纸页”

3. 统一设置 / 确认 / toast 样式

- 所有弹层统一到一套材质与色彩
- 确认框、开发中提示、设置页都应属于一个视觉家族

### 预期收益

- 成本低
- 风格收益极高
- 不会碰战斗核心
- 最适合当前阶段

---

## Phase 2：房间氛围统一

### 目标

把现在已经存在的光照和后处理真正变成“房间叙事”的一部分。

### 范围

1. 定义房间状态氛围

- 普通房：冷蓝黑、呼吸弱
- 战斗中：边缘压暗，危险区域对比上升
- 房间清空：压暗减轻，空气感变松
- 精英房：更强压迫、色温更冷
- Boss 房：更深、更稳、更低频

2. 统一后处理参数

- `SimpleLighting` 不再只做“能看见”
- `TiltShiftSystem` 参数按状态切换
- 补一层全局环境雾或尘粒，而不是靠单一暗角

3. 低血量视觉语言

- 不是简单红边
- 应该像呼吸变重、边缘变脏、世界稍微压近

### 预期收益

- 游戏内画面会第一次真正拥有“封面同款气候”

---

## Phase 3：战斗反馈风格统一

### 目标

把战斗反馈从“有效特效”提升到“有审美方向的反馈”。

### 范围

1. 统一伤害数字

- 普通伤害更收
- 暴击更短促、更利
- 不要继续发成大号彩色漂浮字

2. 统一命中 / 暴击 / 斩击 / 爆炸色彩

- 近战命中偏灰白 + 暗红
- 法术命中按属性微调，但受统一亮度约束
- 奖励反馈和受伤反馈明确区分

3. 死亡与掉落

- 敌人死亡要更“沉”
- 掉落出现要更“可拾取”
- 现在很多东西有反馈，但没有仪式感

---

## 优先级判断

如果只允许先做一轮，我建议顺序固定为：

1. HUD / 暂停 / 面板
2. 房间氛围
3. 战斗反馈

原因很简单：

- HUD 和面板决定“第一眼像不像成品”
- 氛围决定“整局游戏有没有统一气候”
- 战斗反馈决定“爽感是否有高级感”

如果顺序反过来，收益会低很多。

---

## 不建议现在做的事

1. 不建议先大改角色、敌人原画

原因：

- 成本太高
- 容易失控
- 不是当前最大落差来源

2. 不建议先做更多剧情 UI

原因：

- 包装层已经领先
- 现在缺的是游戏内层跟上

3. 不建议一次性把所有 UI 全部换掉

原因：

- 风险高
- 易引入交互回归
- 更适合按 Phase 逐层替换

---

## 建议的下一步执行方式

下一轮不要直接“随便美化”，而是做一个严格的小阶段：

### Sprint A：游戏内 HUD 与暂停界面统一

交付目标：

- 一版新 HUD 结构图
- 一版新暂停界面
- 一版新弹层视觉基线

改动原则：

- 尽量不碰战斗逻辑
- 允许接管现有 DOM / Canvas UI 入口
- 优先把最掉价的 UI 替换掉

---

## 结论

这个项目现在最需要的不是继续加功能，而是把“封面、开场、游戏内”拉回同一套视觉宇宙。

当前最优策略不是大修玩法，也不是重画全部美术，而是：

**先用一轮 UI 与渲染统一，把游戏内从“原型感”拉到“作品感”。**

这件事值得做，而且应该尽快做。~
