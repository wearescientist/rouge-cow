# PLAN_Octopath_Rendering_Roadmap_v0.34

## 一、目标定义

本项目的渲染目标不是“堆更多滤镜”，而是建立接近《八方旅人》的视觉语言：

- 像素角色保持清晰硬边，不被后处理吞没
- 场景具有明确的前景、中景、背景层次
- 光照不是平均照亮，而是舞台式叙事打光
- 景深不只是模糊效果，而是镜头焦点管理
- UI、升级、宝箱、Boss 抽奖等交互层永远位于滤镜上层
- 每个房型、楼层、关键角色拥有可被记住的“签名光源”

一句话目标：

> 用像素资产做“舞台化电影镜头”，而不是做“糊一点的平面俯视图”。

---

## 二、当前项目现状判断

### 2.1 已有基础

- 已有 `HD2DRenderer`、`RoomBlurSystem`、`TiltShiftSystem`、`ColorGradingSystem`
- 已有玩家暗角、房间边缘模糊、环境氛围光
- 已完成 HUD / 交互窗口提升到滤镜上层
- 已有 `SpriteDataRegistry`，具备继续扩展发射点 / 锚点的基础

### 2.2 当前短板

- 画面仍偏“单平面房间 + 全屏后处理”，层次感不足
- 光源多数还是功能光，不是叙事光
- 景深焦点逻辑还只围绕玩家，缺少事件焦点切换
- 商店、Boss 房、宝箱房尚未形成一眼可辨的舞台灯光构图
- 前景遮挡、地面热点、角色局部染色还没有系统化

### 2.3 结论

项目已具备“八方旅人方向”的基础条件，但还停留在“效果模块已接入、镜头语言未成系统”的阶段。

## 三、视觉原则

### 3.1 分层铁律

渲染必须长期稳定分为三大层：

1. `Scene Layer`
   - 地面、墙体、敌人、玩家、掉落物、场景特效
   - 接受景深、氛围、暗角、调色等后处理

2. `Presentation Layer`
   - Boss 出场演出
   - 关键交互高光
   - 角色局部叙事光
   - 可以部分参与镜头语言，但不应被重模糊破坏识别

3. `Overlay UI Layer`
   - HUD
   - 升级、宝箱、武器箱、Boss 抽奖、暂停界面
   - 永远不进入房间滤镜链

### 3.2 光照铁律

- 房间必须有“主光源”和“辅光源”，不能平均亮
- 光照优先服务叙事和焦点，而不是追求真实性
- 每种房型至少有一个可识别的签名光色
- 玩家永远可读，不能因风格牺牲战斗判读

### 3.3 景深铁律

- 景深是镜头焦点工具，不是全局审美滤镜
- 焦点对象必须可切换：玩家 / 事件物 / 房间舞台中心
- UI 与交互卡片不得被景深模糊
- 高速移动时应优先保证可读性

## 四、目标画面拆解

### 4.1 《八方旅人》式观感在本项目中的翻译

不是照抄原作技术，而是提炼以下体验：

- 房间像舞台，有被灯光组织过的视觉重心
- 角色像站在聚光区，而不是漂在平面图上
- 房间边缘自然退后，中央戏剧区更清晰
- 前景、地面热点、边缘压暗共同制造纵深
- 关键对象一眼就能看见，不依赖 UI 文本提醒

### 4.2 本项目最重要的四个视觉支柱

1. 焦点景深
2. 舞台打光
3. 前中后景分层
4. 楼层叙事调色

## 五、阶段路线图

## Phase 1：镜头语言成型

### 目标

把现有“模糊效果”升级为“镜头系统”。

### 内容

- 焦点模式统一抽象为：
  - `player`
  - `roomCenter`
  - `eventTarget`
  - `blend(player, target)`
- 升级、开箱、Boss 抽奖、商店交互时允许临时切换景深焦点策略
- 冲刺、受击、Boss 技能演出时允许动态扩大或收缩清晰区
- 镜头焦点与暗角焦点可分离，不强制完全重合

### 验证标准

- 玩家移动时镜头语言稳定，不抽动
- 事件发生时视线会自然被引导到目标区域
- 不再出现“画面模糊了，但不知道想看哪里”的状态

---

## Phase 2：房间舞台光模板

### 目标

让每种房型拥有“可识别的舞台打光”。

### 房型模板

#### 普通战斗房
- 中央主战区微亮
- 边缘压暗
- 门口有弱引导光

#### 商店房
- 商人所在区域形成暖暗环境中的局部仪式感亮点
- 使用独立签名光源，不与普通房混同

#### 宝箱房
- 宝箱周围形成聚焦热点
- 宝箱未开时热点呼吸，打开后切成奖励演出光

#### Boss 房
- 使用更强的中心舞台感
- Boss 区、玩家区、掉落区允许不同光色层次

### 验证标准

- 关掉文字说明后，玩家也能一眼分辨房型情绪
- 房间不再只靠 UI 或 icon 区分

---

## Phase 3：前中后景分层

### 目标

解决“房间像一整张平图”的问题。

### 内容

- 墙框、门框、柱体、边角装饰进入前景/中景分层
- 前景元素允许轻微模糊和暗化，形成镜头遮挡感
- 地面增加局部热点、阴影、投影，使角色真正落在空间里
- 重要对象附近加入更轻的局部明暗对比，而不是只靠描边

### 验证标准

- 玩家站在房间不同区域时，纵深感明显增强
- 画面不再像“平铺贴图 + 滤镜”

---

## Phase 4：楼层叙事调色

### 目标

让每层的光色关系服务剧情和身份，而不是统一套一个滤镜。

### 内容

- 每层定义：
  - 主色
  - 辅色
  - 高光色
  - 危险色
- 调色系统按楼层切换参数，而不是只改 HUD 主题
- 关键事件允许临时覆写色温：
  - 升级：神圣偏金
  - 商店：幽秘偏紫
  - Boss 奖励：夸张金橙

### 验证标准

- 不看 UI 文字，也能通过光色判断当前层与场景情绪

---

## 六、签名光源计划

### 6.1 商店盲眼商人的紫焰蜡烛

这是本路线图中的首个“叙事签名光源”，优先级高。

#### 设计目标

- 商店 NPC 贴图内的紫色蜡烛成为商店房的视觉识别锚点
- 该光源不只是一个紫色圆圈，而是带有角色局部叙事意义

#### 三层表现

1. 火焰本体
   - 蜡烛位置叠加小型紫焰
   - 颜色构成：紫外焰 + 粉紫过渡 + 蓝白火芯

2. 角色局部染色
   - 商人靠近蜡烛的一侧出现弱紫色边缘光
   - 亮度低于玩家主光，避免喧宾夺主

3. 地面热点
   - 商人脚边投射小范围紫色椭圆光斑
   - 半径小，强调“手边烛火”，不是全房主照明

#### 光源行为

- 缓慢闪烁，不做高频乱跳
- 呼吸节奏偏诡秘、安静、仪式感
- 只在商店房启用
- 未来可扩展为 `npc_shopkeeper.candle` 发射点

#### 验证标准

- 玩家进入商店房时，第一眼就能记住商人的紫焰
- 商店房气质与普通房明显不同
- 紫焰不会把商店打成“霓虹灯房”

## 七、技术策略

### 7.1 坚持当前架构演进，不推倒重来

本项目当前最适合的路径不是直接跳 WebGL 重写，而是：

- 继续沿用 `Canvas + 模块化后处理 + 分层绘制`
- 优先做渲染顺序、焦点逻辑、房型灯光模板
- 在现有系统内建立统一的“焦点 / 光源 / 层级”规则

### 7.2 当前禁止事项

- 禁止因为局部效果不满意就整体切换到全新渲染栈
- 禁止继续堆叠大量同类滤镜掩盖层次问题
- 禁止把 UI 或关键交互重新画回滤镜层

### 7.3 可以接受的扩展

- 为 SpriteData 增加可选发射点定义
- 为房型建立数据化光源模板
- 为事件系统增加镜头焦点切换指令
- 为后处理增加“事件态参数”

## 九、验收标准

只要满足以下条件，才算真正接近目标风格：

- 玩家、敌人、关键交互在任何时刻都清楚可读
- 房型情绪能靠画面而不是文案被区分
- 画面焦点能被镜头语言引导，而不是靠运气
- 商店、宝箱、Boss 奖励等关键节点拥有一眼可辨的签名光源
- 整个画面呈现“舞台化叙事感”，而不是“滤镜堆叠感”

---

## 十、结论

本项目的“八方旅人方向”不应理解为“更强模糊 + 更亮光晕”，而应理解为：

> 用严格分层、叙事打光、焦点景深和签名光源，把像素战斗房间变成一个会引导视线的舞台。~Meow
